# Как вести STREAMHUB на GitHub

## Получить исходники

На странице репозитория нажмите **Code → Copy URL**, затем в терминале:

```bash
git clone <URL-репозитория>
cd streamhub
```

Установщик ищите справа в **Releases** → нужная версия → **Assets**. Кнопка **Code → Download ZIP** скачивает исходники, а не установщик.

## Внести изменение

```bash
git switch main
git pull
git switch -c fix/short-description
# изменить код
node --test tests/*.test.cjs
git add .
git commit -m "fix: описание изменения"
git push -u origin fix/short-description
```

После этого на GitHub откройте **Compare & pull request**. Проверьте список файлов, тесты и откройте pull request в `main`. Для следующей задачи снова обновите `main` и создайте новую ветку.

## Выпустить версию

1. Обновите версию в `src/package.json`, `src/package-lock.json`, надписях интерфейса и сценарии NSIS; дополните `CHANGELOG.md`.
2. Соберите Windows установщик и проверьте запуск, `/api/health`, воспроизведение и обновление установленной версии. Отдельно проверьте SHA-256 установщика.
3. Слейте изменения в `main`, создайте тег `vX.Y.Z` от проверенного коммита.
4. На GitHub: **Releases → Draft a new release → Choose a tag → Attach binaries**. Загрузите `STREAMHUB-Setup-X.Y.Z.exe` как asset релиза, опишите изменения и результаты проверки, затем опубликуйте релиз.
5. Убедитесь, что EXE скачивается и его SHA-256 совпадает с подготовленным файлом.

GitHub не позволяет добавлять файлы более 100 МиБ обычным коммитом. Для установщиков используйте assets релизов; исходники храните в Git. Не коммитьте папки `node_modules`, данные камер, базы, пароли, токены и локальные `.env`.
